# Demo board

A small board with two boundary-scan chips, simulated on a JTAG chain, to try
the plugin without hardware (and to take screenshots).

- **U1** – a microcontroller, *BSDEMO_M32* (QFN-32): data bus, control
  lines, IRQ, I2C, and GPIOs, a button and a status LED on connector J1.
- **U2** – an FPGA, *BSDEMO_F48* (TQFP-48): the other end of the bus, four
  LEDs and an SPI connector J2.

Both chips are fictional; their BSDL files are in `bscan-demo/bsdl/`. The
JTAG chain is TDI → U1 → U2 → TDO.

## Running it

You need Python 3 and OpenOCD; KiCad 9 or newer with the plugin installed.

```sh
python3 demo/demo_sim.py &
openocd -f demo/openocd-demo.cfg
```

Then open `demo/bscan-demo/bscan-demo.kicad_pro` in KiCad, open the PCB and
click **Boundary Scan**. The project's settings (`bscan-demo.bscan.json`)
already assign the TAPs to U1 and U2 with their BSDL files and fill the watch
list.

While the chips are not in EXTEST, their own logic is running: U1 counts on
the data bus (D0–D7), drives a clock (CLK) and blinks STAT; U2 counts on its
LEDs and toggles PWM0/PWM1. The button on J1 (BTN) is pressed for half a
second every four seconds. Click pads to see them.

## Things to try

- **Pins tab:** click pads of U1 and U2 in the PCB editor, add some to the
  watch list.
- **Drive pins:** click an LED pad of U2 (pins 26–29) and use the
  **0 / 1 / Z** buttons, or **Drive selected** (or right-click) in the watch
  list; U2 goes into EXTEST (setup and review first).
- **Interconnect test:** 13 nets are tested (D0–D7, nCS, nRD, nWR, CLK, IRQ).
  The others show why they are not:
  - *nPROG* – fixed by the starting state of U1 pin 11 ("1", set in the
    project so the FPGA stays configured);
  - *PWM0* – its driver U2 pin 47 shares the output enable with pin 30
    (PWM1);
  - *SDA*, *SCL* – other parts on the net (the pull-up resistors R7, R8);
    include them to test them anyway;
  - the LEDs, J1 and J2 – only one boundary-scan pin.
- **Faults:** start the simulator with faults and run the test again:

  ```sh
  python3 demo/demo_sim.py --short D3,D4 --open U2.5
  ```

  `--short NET1,NET2` shorts two nets, `--open REF.PIN` leaves a pin
  unsoldered; both can be repeated. Restart OpenOCD after restarting the
  simulator.

Testing both chips together needs OpenOCD with `jtag scan` (see
[Optional OpenOCD extensions](../README.md#optional-openocd-extensions)).
With a standard OpenOCD only one chip can be in EXTEST at a time, so the
interconnect test between U1 and U2 cannot run; the plugin says so.

## Files

Everything except the two scripts is generated by `generate.py` from one
description of the board (chips, pins, nets, placement, tracks); run it
after changing that description:

```sh
python3 demo/generate.py
```

| File | |
|---|---|
| `generate.py` | the board description and the generator |
| `demo_sim.py` | the JTAG simulator (OpenOCD `remote_bitbang`, port 5555) |
| `openocd-demo.cfg` | OpenOCD configuration for the simulator |
| `bscan-demo/` | the KiCad project (board only, no schematic) with the BSDL files and the plugin's settings |
| `sim/board.json` | chips, boundary registers and nets for the simulator |

The plugin saves its settings to `bscan-demo/bscan-demo.bscan.json` as you
work; `git checkout demo/bscan-demo` restores the original ones.
